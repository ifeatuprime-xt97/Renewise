Introduction

Renewise is a non-custodial subscription paywall platform for Telegram. It lets group and channel admins charge for membership in TON (GRAM), with payments settled directly on-chain — no middleman holds funds at any point.

It is built for two audiences:

  • Community admins who want to monetise a Telegram group or channel without a payment processor or custodian — knowledge communities, investment groups, content channels, professional networks.
  • Developers who want to accept TON payments in their own Telegram bot or Mini App via the Renewise Payments API — no smart-contract knowledge required.

Key properties

  • Non-custodial — funds go directly on-chain. Renewise cannot freeze, reverse, or redirect a completed payment.
  • USD pricing, TON settlement — admins set prices in USD; the TON equivalent is computed at payment time using a live CoinGecko rate and locked in on-chain.
  • Automatic lifecycle — renewal reminders, grace periods, and subscriber removal run without admin intervention.
  • Trustless overpayment refunds — excess TON is held in the vault and released directly to the subscriber's wallet.
  • Mini App dashboard — admins and developers manage everything from a Telegram Mini App.

Open Renewise in Telegram: the full application — admin dashboard, developer dashboard, subscriptions, and settings — lives inside the Telegram Mini App at t.me/Renewisebot. Product updates are posted to t.me/renewise.

Getting Started

For community admins

  1. Open @Renewisebot in Telegram and press Start.
  2. Add the bot to your group or channel as an admin with these permissions: Invite Users / Process Join Requests, Ban Users (and Manage Messages for channels).
  3. Run /createpaywall in a private chat with the bot, or use the setup wizard in the Mini App.
  4. Set your USD price, billing interval (weekly or monthly), and your TON payout wallet address.
  5. Renewise activates the paywall and generates a private invite link for your community.

For developers

  1. Open @Renewisebot in Telegram and open the Mini App.
  2. Switch to Developer mode and create a platform — you receive a test key pair immediately.
  3. Set your payout wallet, then create charges via the Payments API (see the Developer Guide).
  4. When ready for real funds, generate live keys from the dashboard.

Test mode is free: test charges run on TON testnet. Get free test TON from the @testgiver_ton_bot and view transactions on testnet.tonscan.org.

How Renewise Works

The full lifecycle of a paid membership, end to end:

  1. Create / connect your community. The admin adds the bot to their group or channel as admin and runs /createpaywall (or uses the Mini App wizard).
  2. Set membership pricing. USD price + billing interval (7 or 30 days) + payout wallet address.
  3. Renewise generates a private invite link for the group.
  4. A member requests to join → the bot DMs them a payment link (QR code + ton:// deep-link).
  5. The member pays in TON → a per-subscription smart contract (PaymentVault) splits the payment atomically:
    • the admin's share goes directly to their payout wallet,
    • the platform receives its fee,
    • any overpayment above the required amount is held in the vault for a trustless refund.
  6. The bot detects the on-chain payment, approves the join request, and sends a welcome DM.
  7. Before expiry, the bot sends a renewal reminder. If not renewed, the member is removed automatically after the grace period.

The PaymentVault smart contract

One vault contract is deployed per subscription (user × group pair), on first payment, using TON's deploy-on-first-message pattern. The contract address is computed deterministically from the subscription parameters. On renewals, the same contract address is reused.

The fee model, encoded at deploy time:

Buyer sends:     price + buyer_fee + gas_reserve  (0.05 TON)
Admin receives:  price - admin_fee                (direct to payout wallet)
Platform gets:   admin_fee + buyer_fee            (to PLATFORM_WALLET)
Vault holds:     any overpayment above required   (for trustless refund)

Default fees: buyer fee 2.00% (added on top of the price), admin fee 3.30% (deducted from the payout) — a combined platform take of ~5.30%. Per-group overrides are available via the Superadmin panel.

Overpayment refunds

When a member sends more than the required amount:

  1. The vault holds the excess in overage_held (on-chain state).
  2. The watcher detects it and DMs the member asking for their wallet address.
  3. The member replies with their TON address (validated by the bot).
  4. The trigger wallet sends Refund{recipient} to the vault.
  5. The vault verifies sender == trigger_wallet and releases the overage to the member — directly from the vault, with no platform private key involved.

Underpayments

If a member sends less than required, the contract rejects the message with exit code 400 and TON's bounce mechanism returns most of the funds automatically. The bot DMs the member explaining the shortfall.

Developer Guide

Renewise lets you accept TON payments from your own app or service by issuing a charge request against the Renewise vault infrastructure. Your users pay in TON; you receive value in USD-equivalent terms tracked per charge.

Quick start

  1. Open the Renewise Mini App → Developer mode → create a platform. You receive test keys immediately.
  2. Set your payout wallet in the dashboard.
  3. Create a charge with your secret key:
POST /api/platform/charges
Authorization: Bearer sk_test_…
Content-Type: application/json

{
  "amount_usd": 9.99,
  "external_reference": "order_1234",
  "expires_in": 900
}

The response contains a vault_address, the exact required_nano_amount (1 TON = 1,000,000,000 nanoTON), and a payment_url — a ton:// deep-link your user pays from any TON wallet.

Directing your user to pay

  • Telegram Mini Apps (mobile): embed the payment_url behind a "Pay with TON" button.
  • Desktop / web: render the payment_url as a QR code for the user to scan with Tonkeeper or TonHub.
  • Hosted checkout: every charge also gets a hosted checkout page at /checkout/{charge_id} that you can link to directly.

Do not display the raw vault address for manual copy/paste. Renewise uses a deploy-on-first-message architecture to atomically split funds on-chain. The deep-link contains a StateInit payload required to deploy the smart contract. If a user manually copies the raw address and sends TON from an exchange, the contract will not deploy and the payment will get stuck. Renewise has a background trigger-wallet to retroactively deploy and recover these funds, but it delays confirmation.

Checking charge status

GET /api/platform/charges/{charge_id}

Poll this endpoint or — better — rely on webhooks.

Status Meaning
pending Awaiting on-chain payment
completed Payment confirmed on-chain
expired Payment window elapsed without payment
failed Payment received but invalid (wrong amount, wrong chain)

Charge request fields

Field Type Required Description
amount_usd float Yes Charge amount in USD (min 0.10)
external_reference string Yes Your internal order/user ID. Max 255 chars. Unique per platform.
expires_in integer No Seconds until expiry. Default 900 (15 min). Range 60–3600.

Python example

import requests

BASE = "https://your-renewise-host.example.com"
SECRET = "sk_live_…"  # from env var, never hardcoded

def create_charge(amount_usd: float, order_id: str) -> dict:
    resp = requests.post(
        f"{BASE}/api/platform/charges",
        headers={"Authorization": f"Bearer {SECRET}"},
        json={
            "amount_usd": amount_usd,
            "external_reference": order_id,
            "expires_in": 900,
        },
        timeout=10,
    )
    resp.raise_for_status()
    return resp.json()

charge = create_charge(9.99, "order_1234")
print(f"Direct link: {charge['payment_url']}")
print("(Render this URL as a QR code or embed it in a 'Pay' button)")

API Keys

Open the Renewise Telegram Mini App, navigate to Developer → select your platform → Dashboard. You have two independent key pairs:

Key Prefix Environment
Publishable key (live) pk_live_… Mainnet (real TON)
Secret key (live) sk_live_… Mainnet
Publishable key (test) pk_test_… Testnet (free test TON)
Secret key (test) sk_test_… Testnet

Keep secret keys private. Never expose them in client-side code, mobile apps, or public repositories. Rotate immediately if compromised via Dashboard → Regenerate.

Authentication

All API calls must include your secret key in the Authorization header:

Authorization: Bearer sk_live_

The environment (live vs. test) is inferred automatically from the key prefix. A sk_live_ key always routes to mainnet; a sk_test_ key always routes to testnet. Mixing them returns 403 Forbidden.

Rotating keys

  1. Dashboard → API Keys → click Regenerate for the relevant key.
  2. The old key is immediately invalidated.
  3. Copy the new secret key from the one-time alert — it will not be shown again.
  4. Update your server's environment variable.

Environment isolation

Test Live
Keys pk_test_ / sk_test_ pk_live_ / sk_live_

TonScan explorer testnet.tonscan.org tonscan.org

A test-mode charge never touches mainnet. A live-mode charge never touches testnet. This is enforced at both the API authentication layer (key prefix check) and the database level.

Payment Flow

Subscription payments (communities)

  1. A member requests to join the paid group or channel.
  2. The bot DMs them a payment link — a QR code and a ton:// deep-link containing the StateInit payload for the member's per-subscription vault.
  3. The member pays from any TON wallet. The vault contract deploys on first message and splits the funds atomically: admin share → payout wallet, platform fee → platform wallet, overpayment → held in the vault.
  4. The watcher detects the on-chain transaction, verifies the amount, and marks the payment processed (idempotently — a transaction hash can never be processed twice).
  5. The bot approves the join request and sends a welcome DM.

Developer charges (Payments API)

  1. Your backend creates a charge via POST /api/platform/charges.
  2. You direct the user to the payment_url (button, QR code, or the hosted checkout page at /checkout/{charge_id}).
  3. The user pays; the vault splits the funds on-chain.
  4. The watcher confirms the payment and the charge becomes completed.
  5. You're notified via webhook (or you poll the charge status endpoint).

Always use the payment_url. The deep-link carries the StateInit required to deploy the vault contract. Manual transfers to the raw address from exchanges can get stuck (see the warning in the Developer Guide).

Memberships & Renewals

Each subscription is one row per (user, group) pair, with its own vault address, renewal dates, and the price locked in at payment time.

Lifecycle

  1. Active — payment confirmed, member has access.
  2. Renewal reminder — sent 3 days before expiry (configurable via REMINDER_WINDOW_DAYS).
  3. Grace period — 3 days after expiry (configurable via GRACE_PERIOD_DAYS) during which the member can still renew.
  4. Removal — if payment isn't received, the member is removed from the group automatically.

Renewals

  • Renewing reuses the same vault contract address — the member pays to the same address and their access is extended.
  • Price changes only affect new payments: existing subscribers keep their price_locked_in until their next renewal.
  • Billing intervals are weekly (7 days) or monthly (30 days).

Comped access

Admins can comp a member by Telegram user ID — granting free access without payment, from the Mini App or the bot's admin menu.

Wallets & Settlement

Non-custodial settlement

Renewise never holds user funds. Every payment is split on-chain by the PaymentVault smart contract in the same transaction it is received:

  • Admin payout — the admin's share (price minus admin fee) goes directly to their registered payout wallet.
  • Platform fee — buyer fee + admin fee goes to the platform wallet.
  • Overpayment — held in the vault's overage_held until released to the member via the trustless refund flow.

The split is encoded in the contract at deploy time and cannot be changed retroactively. A completed on-chain split is final.

Changing your payout wallet

  • First setup: simply enter your TON wallet address — no passkey required.
  • Changing an existing wallet: requires your 4-digit passkey and is scheduled with a 24-hour delay. Any pending change can be cancelled within that window, and a new request supersedes the old one.
  • On mainnet, testnet wallet addresses are rejected outright — payouts would never arrive.

Lost passkey? Passkeys are bcrypt-hashed and never stored in plaintext. There is no self-service reset — contact support.

USD pricing, TON settlement

Admins set prices in USD. The TON equivalent is computed at payment time using a live CoinGecko rate (with fallback) and locked in on-chain for the life of the subscription.

Notifications

For members (bot DMs)

  • Payment link when they request to join a paid community
  • Welcome message when their payment is confirmed and access is granted
  • Renewal reminder before expiry
  • Overpayment refund request (asking for their wallet address)
  • Underpayment explanation (when a payment bounces)
  • Notice when access ends because a paywall was closed

For admins (bot DMs + Mini App)

  • Paywall activation confirmation
  • Wallet change scheduling and activation notices
  • Revenue and member activity in the Mini App dashboard and analytics

For developers (webhooks)

Instead of polling, configure a webhook to receive real-time charge events. In the Dashboard → Webhook → Edit, enter your HTTPS endpoint URL. You receive a whsec_… signature secret — save it immediately, it is only shown once.

Renewise sends an HTTP POST to your endpoint:

POST /your-webhook-handler
Content-Type: application/json
Renewise-Signature: 

{
  "id": 42,
  "external_reference": "order_1234",
  "status": "completed",
  "amount_usd_cents": 999,
  "tx_hash": "abc…def"
}

Verifying the signature

import hmac, hashlib

def verify_renewise_signature(payload: bytes, header: str, secret: str) -> bool:
    expected = hmac.new(secret.encode("utf-8"), payload, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header)
const crypto = require("crypto");

function verifySignature(rawBody, header, secret) {
  const expected = crypto
    .createHmac("sha256", secret)
    .update(rawBody)
    .digest("hex");
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(header)
  );
}

Always use a constant-time comparison (hmac.compare_digest / timingSafeEqual) to prevent timing attacks.

Return HTTP 200 within 5 seconds to acknowledge receipt. Any non-2xx response or timeout is recorded as a failed delivery and visible in your Dashboard → Webhook → Recent Deliveries. The webhook signing secret can be rotated without changing the URL.

Security

Authentication

  • Mini App requests are authenticated via Telegram's initData HMAC-SHA256 mechanism, verified server-side against the bot token. initDataUnsafe is never trusted for authentication decisions.
  • Every Mini App endpoint that touches group-scoped data performs an ownership check — the requesting Telegram user must be the registered admin of that group.
  • Developer API calls authenticate with the platform secret key (Bearer token). Live secret keys are SHA-256 hashed before storage.

Non-custodial architecture

  • Renewise cannot freeze, reverse, or redirect a completed on-chain payment.
  • The trigger wallet — the only hot wallet in the system — holds roughly 2 TON for gas. If compromised, an attacker can only trigger refunds the contract has already validated; they cannot redirect funds or drain any other balance.

Operational safeguards

  • All admin actions are logged to an append-only audit log.
  • Wallet changes are delayed by 24 hours by default and can be cancelled within that window.
  • Wallet passkeys are bcrypt-hashed, never stored in plaintext.
  • Rate limiting is applied to all API endpoints (5–60 req/min depending on the endpoint).
  • Transaction processing is idempotent — a transaction hash can never be processed twice.
  • Test and live environments are isolated at the key, network, and database level.

FAQ

Does Renewise hold my money?

No. Renewise is non-custodial. Payments are split on-chain by per-subscription smart contracts — the admin's share goes directly to their wallet, the platform fee to the platform wallet. Renewise cannot freeze, reverse, or redirect a completed payment.

What do members need to pay?

Any TON wallet — Tonkeeper, TonHub, @wallet, or an exchange wallet that supports deep-links. Members pay in TON (GRAM); the price is set in USD and converted at payment time.

What happens if a member overpays?

The excess is held in the vault contract. The bot DMs the member asking for a wallet address, then a dedicated trigger wallet releases the overage directly to them — trustlessly, with no platform private key involved.

What happens if a member underpays?

The contract rejects the payment with exit code 400 and TON's bounce mechanism returns most of the funds automatically. The bot DMs the member explaining the shortfall so they can retry.

Can I change my price?

Yes — from the Mini App or the bot's admin menu. Existing subscribers keep their locked-in price until their next renewal; only new payments use the new price.

Can I change my payout wallet?

Yes, protected by a 4-digit passkey and a 24-hour delay with a cancellation window. On mainnet, testnet addresses are rejected outright.

What happens when a membership expires?

A renewal reminder is sent 3 days before expiry. After expiry there's a 3-day grace period. If the member still hasn't renewed, they're removed from the group automatically.

Can I give someone free access?

Yes — admins can comp a member by their Telegram user ID from the Mini App or the bot's admin menu.

Can I use Renewise in my own bot or Mini App?

Yes. The Renewise Payments API lets you create charges, get a payment URL and hosted checkout page, poll status, and receive signed webhooks. See the Developer Guide.

How do I test without real money?

Use test keys (sk_test_…) — charges run on TON testnet with free test TON from @testgiver_ton_bot. Live keys settle real funds on mainnet.

Follow the official Renewise channel: t.me/renewise.
